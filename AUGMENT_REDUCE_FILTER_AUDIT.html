7 What to fix before the next sweep — ranked by P&L risk (accents on missing translations)

🔴 P1 — PARTIAL_PROFIT_LOCK + PEAK_GIVEBACK are invisible to the vector
Live closes ~50% of winning positions via PPL 50% (62.5% stocks) at 0.5–1.5% + BE arm and PEAK_GIVEBACK drop 50% of peak. Vector ledger has no PPL/PEAK reduce block — the only partial close is the 2-regime QUICK_REDUCE (15% of winners). Result: vector backtest overstates holding time, understates fees, and the TEMPLATE REDUCE rows for these two families always return delta 0 (dead knobs) so the sweep never learns they help live P&L.
Fix: simulate_one: after live_pnl_pct + held_bars, check PPL step1 (gain≥PCT → reduce FRAC), step2 arm (gain≥ARM → stop=entry*(1+BE_BUFFER)), and PEAK_GIVEBACK (peak→live drop). Mirror ez 49292 / tradier 16778.
🟠 P2 — AUGMENT_MIN_GAIN trio + 4 AUGMENT blocks + HIGH_GAIN/DYNAMIC/RECOVERY are hash-only
Live adds on 4 conviction blocks (BLOWPAST conv90, WT_CROSS 80, WT_3TF 70, HTF_TREND 65) plus HIGH_GAIN direct loop (gains >0.5*MIN_GAIN + wt1_1h aligned via add-block) and RECOVERY after partial closes. Vector collapses all to adx_1h / relative_volume_1h / rsi_1h placeholder + 1/503 hash. Spinning the 6-row AUGMENT_MIN_GAIN_PCT sweep (0.5/1/1.5/2/3/5) in TEMPLATE → delta 0 every value — not because MIN_GAIN doesn't matter, but because vector ignores it. Same for the 4 live blocks that are the actual high-conviction adds.
Fix: compute_augment_signals: read AUGMENT_MIN_GAIN_PCT (branch bounce vs breakout), evaluate 4 blocks via wt1_3m/wt1_15m/htf_trend, add HIGH_GAIN wt1_1h gate + RECOVERY age/band logic.
🟣 P3 — TRA_DISABLE_AUGMENT divergence (stocks silently overstate)
Live stocks TRA_DISABLE_AUGMENT=True means no augment ever on Tradier (AAPL/MSFT/NVDA etc flat after entry). Vector simulate_one does not check this master kill — compute_augment_signals still returns bounce+pyramid true on TRADIER symbols, so any simulated stock gain that relies on pyramid adds is unachievable live. Every stock AUGMENT_* row that might show winner in backtest is unpromotable without first flipping this live default and re-verifying via backtest_v12_engine scalar.
Fix: simulate_one: if MODE=='tradier' and cfg.TRA_DISABLE_AUGMENT: augment_sig[:]=False at top of loop; require config_tradier live change + scalar verify before promotion.
🔵 P4 — 50× FILTER_TF selectors are dead knobs
Every *_FILTER_TF = OFF/D/4h/15m/1h column in TEMPLATE is a TF selector. Vector reads the string then discards it — the mask never switches on D vs 4h. Spinning any TF column alone → delta 0. Only becomes meaningful once its parent (PPL/PEAK/BOUNCE/REGIME) is causal. Sweep currently wastes 50 params × 5 TF values × 148 symbols on no-ops.
Fix: Either gate the sweep to skip TF selectors when parent is missing (mark UNRESOLVED per lifecycle attachment contract) or wire each filter's _safe(npz, tf_field, n) correctly.
