## Red wiring defect found and repaired

The first pass produced zero validation exits for 19 of 20 selected rows. That
was not gray strategy performance and was not absent data. The adapter had
made GR edge-triggered once across the entire history. If an opposite vote was
already active when a position opened, or if a chronological fold began after
the original edge, the exit was forgotten forever.

GR direct exit is a level condition in the actual path. The repaired adapter
checks it on each new completed HTF update while a position is active. The
first-pass zero-exit rows are retained but relabeled
`RED_DIAGNOSTIC_INERT`; they cannot be read as hold winners.

- every repaired selected row made 36–286 exits in untouched validation;

  eligible completed updates per key and 224–995 aggregate fills;

  histogram and HA input exists on every tested 15m/1h/4h/D series;
- future HTF source count and bars-flat-beyond-reclaim are zero.

Thus the path is now connected. Its remaining problem is excessive breadth and
poor timing, not silence.

## Knob responsiveness and next range

The repaired path responds, but two tested threshold ranges are empirically
degenerate:

| knob | comparison groups with a changed fold fingerprint | interpretation |
|---|---:|---|
| `min_tfs` 1/2/3 | 0 / 2,880 | inert over this score range; raw votes already qualify enough TFs |
| `min_indicators` 1/2 | 0 / 4,320 | inert over this score range; 1–2 is below observed raw vote counts |
| weighted score | 252 / 1,440 | connected, but low thresholds are saturated |
| TF weights | 252 / 2,880 | connected, but often masked by score saturation |
| profit gate | 2,160 / 2,160 | fully responsive |

`min_tfs` and `min_indicators` are red range diagnostics, not disconnected
code: unit cases prove both gates operate, while current real rows show that
their 1–3 and 1–2 ranges do not alter eligibility once the score gate is
applied. Repeating these ranges is prohibited.

The next preregistered GR experiment should:

1. drop score 4/6 and move the raw-indicator floor materially above 2;
2. require at least one explicitly named high-timeframe vote instead of merely
   increasing a pooled count;
3. use the responsive profit gate but add price structure/top confirmation so
   an always-broad opposite vote does not churn every reentry;
4. treat TTD's 108 final-pass arms and UUUU's 102 robust-alpha arms as discovery
   boundaries, never as promotions;
5. retain the same frozen entry, per-TF audit, side mirror and reclaim ledger.
