## Baseline and coherent-bundle procedure

1. Freeze key, side, account, date range, NPZ SHA, code SHA, costs, capacity and
   fold boundaries. LONG and SHORT are separate books.
2. Run the default exact baseline. The default must be present in every test
   grid. A knob whose two values reproduce its fingerprint is red `RECONNECT`;
   do not sweep its children.
3. For vector-supported paths, screen whole bundles vector-first. Exact-only
   paths go directly to c5 ENGINE. A bundle contains ENTRY, AUGMENT, REDUCE,
   EXIT, REENTER/RECLAIM and sizing assumptions. It is not a bag
   of independently promotable cells.
4. Use two discovery folds, freeze the winner, then use untouched validation.
   Early-stop a bundle as soon as a discovery fold cannot clear its gates.
5. Fill the current top ten keys per side plus `IBIT_LONG` and `PLTR_SHORT`
   first. Allocate nine claims to positive/promising handles and one to
   deterministic exploration. A structurally wired family/combination that is
   negative at every parameter moves to one-in-five keys; after another
   stratified all-negative batch it moves to one-in-ten. Inert/unwired/data-
   invalid rows never justify demotion; a positive result on two sampled keys
   restores full priority.
6. Only strict vector survivors enter exact replay. Exact replay must prove
   fills, partial P&L, capacity, solvency, completed-parent causality, side
   separation, mandatory reentry, and the same capital/TIM metric.
7. Promotion changes only the explicit per-symbol overlay after a fresh
   no-position or controlled transition gate. Preserve the prior overlay hash
   and exact receipt for rollback.

## Invalidation is directional, but controls are cyclic

- A data, side, account, cost or capital change starts a new campaign. Every
  prior cell is stale.
- A master change invalidates every setting in its family and all bundles that
  consume the family.
- A cross-cutting guard change invalidates the complete schedule. These guards
  come before entries; they are not a final layer after sizing.
- An entry change invalidates every downstream result because it changes which
  trades exist.
- An exit change invalidates reentry and sizing. It also requires the frozen
  entry control again, because a “better exit” on different entries is not an
  exit comparison.
- A reentry change requires the entire entry→exit→reentry cycle and invalidates
  later exit evidence because reopened positions create a new exit population.
  An exit-price obligation may be temporarily vetoed by WT/stoch conditions,
  but cannot be forgotten.
- A sizing change requires the coherent schedule replay because capacity can
  reject an add and alter subsequent actions. Signal timestamps may be cached
  only after exact schedule-fingerprint equality. Size may improve dollars; it
  cannot manufacture timing alpha.
- An unknown/global guard is conservative: retest the full bundle.

The JSON `retest_rules` and each CSV row's `retest_class` make these decisions
executable by a scheduler.

## Color and evidence definitions

| color | definition | action |
|---|---|---|
| red | zero real closes, same-value fingerprint, stale/wrong contract, future HTF, capacity/solvency/partial-accounting failure, reentry violation, disconnected or degenerate knob | repair/quarantine; never rank |
| gray | valid measured evidence that does not beat side-aware B&H-or-cash and the same-fold control; includes losing DC-low emergency churn | retain so it is not retested routinely; eligible only for the 10% exploration lane |
| green | current-contract c5 exact evidence with real closes, changed fingerprint, no red failure, `gain_per_mo > 2.0`, and positive delta over side-aware B&H | promote under the 2026-07-30 TRB rule; TIM remains descriptive |
| white | untested, incomplete, or not comparable | schedule after dependencies |

Green is not “positive P&L.” In a rising LONG book it must beat LONG B&H; in a
SHORT book it must beat side-aware SHORT B&H or cash. LONG and SHORT P&L are
never pooled.

## Fold, data and capital contract

- Frozen chronological folds: 35% discovery-1, 35% discovery-2, 30% untouched
  validation for the current bundle screen.
- HTF features use only completed parent bars. Stocks disclose whether each 5m
  bar is native or interpolated from the containing 15m bar; interpolation is
  not hidden or treated as native history.
- B&H uses the side-aware move of one $2,000 unit. Sandbox strategy capacity may
  reach $16,000, but leverage is reported separately.
- Return-on-deployment uses net fill P&L divided by **pre-cost committed fill
  notional integrated over the complete fold**. The denominator is never marked
  notional.
- Publish binary time in market separately. It is an optimization/exposure
  diagnostic, not a TRB matrix promotion gate.
- A per-trade percentage sum, unqualified Sharpe, levered-vs-unlevered multiple,
  or ratio with near-zero B&H is not promotion evidence.
