# c4 Current-Matrix Red/Identical-Cell Audit — 2026-07-29

## Fixed locally

### P0 — stale same-c4 MTF rows could rerun forever but never be replaced

The companion repair correctly rejects old MTF receipts with `TF="None"` or
missing companions. However, `param_results_store.insert_cell()` previously
refused every same-tier/same-contract replacement. The daemon would rerun the
cell, the store would discard the new result, and the next pass would rerun it
again.

The store now permits an explicit, MTF-only same-contract receipt refresh when
the canonical override receipt materially differs. The displaced row is
archived as `SAME_CONTRACT_RECEIPT_REFRESH`. Formatting-only JSON changes do
not qualify.

### P0 — invalid same-c4 cells could never recover

The dedupe correctly ignores structurally invalid cells, but the same store
rule also prevented a later valid rerun from replacing an invalid row under
the same contract. Valid repaired reruns can now explicitly replace an invalid
same-contract row and archive it as `SAME_CONTRACT_VALIDATION_REFRESH`.
Invalid reruns cannot displace valid evidence.

### P0 — exact preflight rejected sub-settings before the recipe enabled them

The exact wiring gate inspected the live/default family master. Therefore
sub-settings under default-off families such as:

- `LR_BAND_HARVEST_FRAC`
- `LR_BAND_HARVEST_HI`
- `STDEV_REJECT_EXIT_RETURN`
- `STDEV_REJECT_EXIT_ZONE`

were classified `RED_GATED_OFF` before an engine run, even though
`matrix_cell_overrides()` explicitly enables their family master.

The daemon now supplies the master state from the complete isolated-cell
recipe to the gate. All 408 selected six-pilot cells were audited; none remains
blocked by a live/default-off master.

### P0 — default sub-settings were falsely skipped as baseline aliases

The old shortcut compared only the proposed value with the ladder-floor/config
default. For a sub-setting, that is incomplete: the recipe also enables the
family master. The default threshold/TF with its master on is often the most
important strategy path, but it was skipped without execution.

Alias detection now compares the complete effective recipe against the ladder
floor plus config fallbacks. Default sub-settings with an activated master are
run. Only a genuinely identical recipe is elided.

The six selected packs contain 45 genuine master-off baseline aliases:

- 8 per long key;
- 7 per short key.

They no longer keep the daemon's remaining-work scan nonzero forever.

### P1 — historical dead-knob verdicts could suppress repaired c4 work

`data/useless_knobs.json` is generated by a historical-only tool that does not
bind evidence to c4 fingerprint, side, isolated family activation, or the
current baseline. The daemon nevertheless used it unconditionally.

Repaired campaigns now ignore that historical prune file. Historical
campaigns retain the existing behavior.

### P1 — one inert numeric result was reported as full `RECONNECT`

The workbook marked a parameter `RECONNECT` when every result seen so far was
inert, even if only one numeric value had been tested. One value proves only
`INERT_AT_VALUE`, not disconnected wiring.

Numeric settings now require at least two values on the same key before the
workbook can label the whole knob `RECONNECT`. A boolean non-default remains a
valid two-state test because the accepted baseline supplies its default state.

### P1 — MTF lookback description contradicted the source

The workbook described `MTF_DC_REJECT_EXIT_LOOKBACK` as having no read site.
`TradierManage.evaluate_stop` reads both DC and BB lookbacks. The descriptions
now explain their current timing behavior and compound-parent requirement.

## Still open, ranked

### P0 — trade fingerprints omit outcome dimensions

`trades_fingerprint()` hashes only entry timestamp, exit timestamp, and
`pnl_pct`. It omits quantity, side, realized cash P&L, partial-close quantity,
exit reason, exposure path, and audit metrics. Sizing or partial-exit changes
can therefore be falsely marked identical/inert.

Do not silently change this inside c4: existing baseline fingerprints would
be incomparable. Introduce a versioned outcome fingerprint and rebaseline in
the next result contract, retaining the old fingerprint for forensic history.

### P1 — activation-only parents are guaranteed inert when tested alone

`MTF_EXIT_USE_COMPOUND=True` is scheduled as an activation ancestor while all
child exits remain off on the ladder floor. That standalone cell can produce
only the baseline schedule. It should be reported as `ACTIVATION_ONLY` and
validated through its child bundles, not called `RECONNECT`.

The same rule should be applied to any dependency ancestor whose only function
is to expose child paths.

### P1 — true baseline aliases remain blank numeric cells

The daemon correctly avoids rerunning a recipe identical to the accepted
baseline, but the canonical matrix currently displays no number for that
logical value. The exporter should show the accepted baseline number with an
explicit `BASELINE_ALIAS` provenance/state. It must not pretend a second engine
run occurred or count the alias as independent wiring evidence.

### P1 — MTF companion TF/lookback grids are not yet explored

c4 safely restores the audited defaults (`DC/BB 1h, lookback 5`; `WT 15m`),
but these companion fields are not in the current sweepable dependency pack.
Testing alternative TF/lookback values should be a versioned follow-up
contract; do not modify the frozen hashed c4 interdependency JSON in place.
